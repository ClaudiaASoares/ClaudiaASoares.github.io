# SEO audit of claudiaasoares.github.io

Audit date 13 October 2026, Europe/Lisbon. The website can be crawled. The repair priorities are the broken ASTRA link, missing meta descriptions, published template content, and publication metadata. Mobile loading also needs work. This audit documents observed responses and proposed fixes. Website source files were not edited.

The audit fetched all 91 distinct URLs in the XML sitemap and 18 additional internal link destinations. It checked 62 distinct internal asset URLs and three HTTP response probes. All sitemap URLs returned HTTP 200. The sitemap contains 93 entries because two URLs appear twice. Of the 91 distinct sitemap URLs, 87 serve HTML and four serve PDFs. All 87 HTML pages lack a meta description. A standalone `/404.html` adds one further successful HTML response outside the sitemap.

The [evidence file](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/_audits/seo-2026-10-13-evidence.json) records the URL inventory, response statuses, page metadata, and failed asset URLs. Terms are defined in [CONCEPTS.md](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/_audits/CONCEPTS.md).

P1 indicates a repair to prioritise. P2 addresses discovery, content, or page experience. P3 addresses presentation and maintenance. These priorities are an assessment of the findings, not a prediction of ranking gains.

**Broken featured paper.** The [ASTRA publication URL](https://claudiaasoares.github.io/publication/2026-09-01-ASTRA-ADMM-Accelerated-Topology-Reconfiguration-for-Dynamic-Satellite-Constellations) returned HTTP 404 in the crawl and a second GET request. It is the first selected paper on the homepage and is absent from the XML sitemap and publications archive. The local ASTRA Markdown page exists as an untracked file. The homepage entry is in [selected_recent_papers.yml](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/_data/selected_recent_papers.yml:2). Publish the intended page at the existing link target and confirm HTTP 200, sitemap inclusion, and discovery from the publications archive. Preserve the paper's title and accepted venue metadata.

**Meta descriptions.** The [SEO include](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/_includes/seo.html:23) computes `seo_description` but never emits a meta description. Some pages contain Open Graph descriptions and Schema.org description microdata. These do not supply the missing element. Add the head tag and retain escaping. Write descriptions for the homepage and navigation pages, then generate publication descriptions from their abstracts. Google may choose page text instead of the supplied description. This repair gives it a page-specific candidate for the search snippet. [Google's meta description guidance](https://developers.google.com/search/docs/appearance/snippet).

Proposed homepage metadata is `Cláudia Soares | Trustworthy Machine Learning at NOVA` for the page title and `Cláudia Soares researches trustworthy machine learning at NOVA University of Lisbon, using optimisation, physics and probability for healthcare and space.` for the meta description. Give inner pages a concise name suffix and preserve full publication titles. Change the group page title from `Group` to `TrustworthyML@NOVA`. Descriptive titles help readers assess relevance. Google can generate a different title link. [Google's title link guidance](https://developers.google.com/search/docs/appearance/title-link).

**Published template content.** The live output includes `/markdown/`, `/non-menu-page/`, `/archive-layout-with-content/`, `/markdown_generator/`, and four sample blog URLs. The fourth sample blog URL displays a post dated 1 January 2199. It collides with another post at the same permalink. The HTML sitemap and page archive expose these pages. Empty categories and talks pages, the sample tag and year archives, and `/talkmap/map.html` also need review. Exclude generator documentation in the build configuration and remove unused examples from published output. Retain useful research and teaching content. If a page must remain public but should be excluded from indexing, add a robots `noindex` meta tag and remove it from the sitemap. The existing SEO include needs support for emitting that instruction. Sitemap exclusion alone does not prevent indexing, and blocking crawling can prevent a crawler from seeing `noindex`. [Google's indexing controls](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

**Publication discovery.** The 50 live publication pages have no `citation_*` tags. Twenty-one contain links, a project identifier, or BibTeX without an abstract paragraph. Another page contains a list of subject terms. CLASP, Satellite Safe Margin, and the multi-token federated learning paper are among the pages without abstracts. Seven publication pages also lack an HTML link to the paper in their content or citation header. Add the full author-written abstract and a working DOI, publisher, or preprint link. Keep additions in the [BibTeX source](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/markdown_generator/pubs.bib) and extend the [generator](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/markdown_generator/pubsFromBib.py:479), so regeneration preserves the metadata. Export title, individual authors, publication year or verified date, and venue fields into the HTML head. Use a year when the precise publication date is unknown. Do not derive a publication date from a filename or use 1 January as an asserted day of publication.

Google Scholar requires a separate URL with the full author-written abstract visible to readers. Its `citation_pdf_url` guidance requires the PDF to be in the same subdirectory as the HTML abstract. Preserve external arXiv and publisher URLs as reader links. These findings concern this website's publication pages. Paper indexing through publishers or arXiv was not assessed. [Google Scholar inclusion guidelines](https://scholar.google.com/intl/en/scholar/inclusion.html).

TBT does not substitute for Interaction to Next Paint. [Web Vitals documentation](https://web.dev/articles/vitals). The homepage was inspected at 390 by 844 pixels and had no horizontal overflow. Add an accessible name to the [menu button](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/_includes/masthead.html:7) and review link and footer colours.

**Identity and sharing metadata.** The live Person JSON-LD parses, but its `sameAs` field is null. Add verified ORCID, Google Scholar, and other public profile URLs. A ProfilePage on the homepage can identify the Person as its `mainEntity`. Populate affiliation and image only from verified information. This is an opportunity to describe the person more precisely. It is not evidence of a structured data penalty or a guaranteed search feature. [Google's ProfilePage guidance](https://developers.google.com/search/docs/appearance/structured-data/profile-page).

All checked successful HTML pages lack `og:image`. The homepage also lacks `og:type`. Add a relevant sharing image and emit `website` for ordinary pages. The [SEO include](/Users/claudia/Documents/GitHub/ClaudiaASoares.github.io/_includes/seo.html:86) currently checks page images without using `site.og_image` as an Open Graph fallback. Setting that configuration value alone will not fix the missing image property. Its existing code also emits Organization JSON-LD when `site.og_image` is set. Keep the personal website's entity type tied to its content. Format Open Graph locale as `en_US`. These changes target sharing previews. [Open Graph protocol](https://ogp.me/).
